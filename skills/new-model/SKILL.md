---
name: new-model
description: Make a new provider model (for example the next Sol) work in xcode and the default, prove it with real turns, and install it on Alpha, Omega and Delta in one pass.
---

Work on Alpha in `~/Projects/waozixyz/xcoder` (it holds the latest master). Never print tokens or account details. Logins: Alpha `~/.codex`; Omega `~/.codex` (codex-1) and `~/.config/harmony/codex/accounts/account-d369c369a25044208f83` (codex-2); Delta has its own copies of both. Never copy credential files between machines. Harmony's own default and tier mapping belong to the Harmony task on Omega; send it the model ID as soon as you have it.

1. **First 2 minutes, before reading code:** for every login run `CODEX_HOME=<home> xcoder exec --skip-git-repo-check --ephemeral "Reply PONG"` (full path `~/.local/lib/xcoder/bin/xcode` over SSH). A usage-limit error rules that login out for turns; pick the turn login now. On each host time `getent ahosts chatgpt.com`: over 1 s means broken DNS (Omega 2026-11-17: its IPv4 Quad9 servers timed out, 8 s per lookup). xcode's catalog request has 5 s, DNS included, and silently falls back to the bundled table.
2. **Live list:** `CODEX_HOME=<home> xcoder debug models > live.json`; print only slug, priority, visibility, context, efforts. If it equals `xcoder debug models --bundled`, the fetch failed (step 1). Stop before changing defaults if no login lists the model.
3. **What is new:** diff the new entry against the previous Sol in `live.json`. Check each `experimental_supported_tools` name with `rg` in `codex-rs/core/src/tools/spec_plan.rs` (unknown names are ignored, not errors). Look upstream only for new `ModelInfo` fields: `gh api 'repos/openai/codex/commits?since=<date>'`. Port nothing else.
4. **Bundled entry:** insert the live entry into `codex-rs/models-manager/models.json` in the bundled key order (the keys of the existing Sol entry), with a priority below every other entry, leaving the other entries untouched (`json.dumps(indent=2, ensure_ascii=False)` round-trips the file exactly). `xcoder debug models --bundled` must list it first. `failed_catalog_fetch_defaults_to_newest_bundled_sol` checks that the newest bundled Sol is the default.
5. **Build:** only through `make` (it exports `ZIRAN`; a raw `cargo` without `ZIRAN=ziran` reruns every Ziran build script and the next `make` rebuilds the workspace). Run it detached so a session restart does not kill it: `systemd-run --user --unit=xcoder-build --slice=harmony-agents.slice --working-directory=$PWD --setenv=PATH="$PATH" --setenv=HOME="$HOME" bash -c 'exec build-queue -- make -j2 all > build/build.log 2>&1'`. Alpha has 15 GiB: use 2–3 jobs. If the memory guard stops it, finished crates are kept; rerun with fewer jobs (the final `codex-cli` link alone: `-j1`).
6. **As soon as `build/bin/xcoder` exists, start the real turns in the background:** copy `build/bin/xcoder` and `build/bin/codex-code-mode-host` to `/tmp/xcode-<model>-build/` on the turn login's host, then `python3 -I scripts/model-turns.py /tmp/xcode-<model>-build/xcoder /tmp/xcode-<model>-turns --model <slug> --codex-home <home>`. All 12 lines (plain, shell, patch × low, medium, high, xhigh) must say ACCEPTED. About 15 s per turn on good DNS, 70–90 s on Omega's broken DNS.
7. **Tests, meanwhile, one at a time:** models-manager: `systemd-run ... --setenv=ZIRAN=ziran --setenv=PATH=$PWD/build/toolchain/bin:$PATH --setenv=CARGO_HOME=$PWD/build/cargo-home --setenv=CARGO_TARGET_DIR=$PWD/codex-rs/target bash -c 'exec build-queue -- cargo test --manifest-path codex-rs/Cargo.toml --profile local -p codex-models-manager --lib > build/mm.log 2>&1'`. Then the certified suite from an unrestricted host shell (agent shells have NoNewPrivs, so bubblewrap fails): `ssh omega`, `ssh -F ~/.ssh/alpha.conf alpha`, and there `systemd-run` with `PATH=$HOME/.local/bin:...`, `XCODER_ZIRAN_TOOLCHAIN=$(ziran pkg path ziran)` and `build-queue -- make -j2 test`. Passing prints "Local suite passed; installation receipt saved for the tested binaries"; `backup/xcoder-validation.json` must hold the binary's sha256.
8. **Commit and push:** a line under Unreleased in `CHANGELOG.md`; commit only your files from a private `GIT_INDEX_FILE` (`git read-tree HEAD`, `git add`, commit, then `git reset -q -- <files>` in the real index) as `Waozi <waozi@proton.me>` alone, no co-author lines; `git push origin master`. No version bump, tag or release.
9. **Install:** Alpha `make install`; then `scripts/install-xcoder-remote.sh omega` and `scripts/install-xcoder-remote.sh delta` (Delta goes through Omega's installed copy; its link is slow, about 10 minutes). Files are renamed into place, so running sessions keep working until they restart.
10. **Config pins:** `grep -n '^model *=' <home>/config.toml` for every login on every host. A pin to an older model keeps plain `xcode` on it. Remove the line (Harmony never reads it) under an exclusive `flock` on `config.toml.harmony-config.lock`, writing the file atomically.
11. **Verify each host:** `CODEX_HOME=<home> ~/.local/lib/xcoder/bin/xcode exec --skip-git-repo-check --ephemeral "Reply with exactly the word PONG"` must print `model: <slug>` and, on a login with quota, PONG. A usage limit or "access token could not be refreshed" is an account problem for the owner, not a model failure; report it.
12. **Report:** model ID and properties, the turn table, tests with their results, the commit link, installs per host with sha256, account and DNS problems, and that running sessions get the model when they restart.
